# Curiosity Day

Мобильное приложение-дневник: записывай, что удивило, что необычного сделал(а), и свои выводы. Календарь с цветными маркерами показывает, какие разные получаются дни.

Работает как сайт и устанавливается на экран телефона (PWA). Хостинг — GitHub Pages, база и вход — Supabase.

Описание продукта и этапов — в `TZ.md`. Правила для агента — в `AGENTS.md`.

Адрес сайта после публикации: `https://ВАШ-ЛОГИН.github.io/curiosity-day/`

> Названия кнопок и пунктов меню в GitHub, Supabase и Google Cloud иногда меняются. Если пункт называется иначе, ищите похожий по смыслу.

## Настройка с нуля

Порядок важен: сначала GitHub и Supabase, потом Google. Этап 0 (каркас и деплой) можно запускать, пока вы настраиваете остальное.

### 1. GitHub

1. Репозиторий `curiosity-day` публичный (создан).
2. Загрузите в него файлы: `TZ.md`, `AGENTS.md`, `README.md` и папку `design/` (Add file → Upload files).
3. **Включить публикацию:** Settings → Pages → в поле Source выберите **GitHub Actions**.
4. **Добавить ключи для сборки** (после шага 2 ниже): Settings → Secrets and variables → Actions → New repository secret. Создайте два секрета:
   - `VITE_SUPABASE_URL` — адрес проекта Supabase;
   - `VITE_SUPABASE_ANON_KEY` — публичный ключ Supabase (anon / publishable).

### 2. Supabase

1. Зайдите на supabase.com, создайте аккаунт и новый проект (New project). Запомните пароль базы, но никуда его вставлять не нужно. Регион выбирайте ближайший к вам.
2. Когда проект создастся, откройте Project Settings → API (или API Keys). Скопируйте:
   - **Project URL** — это `VITE_SUPABASE_URL`;
   - **публичный ключ** (anon / publishable) — это `VITE_SUPABASE_ANON_KEY`.
3. **Секретный ключ (service_role) нигде не используйте и никому не показывайте.**
4. Authentication → URL Configuration:
   - Site URL: `https://ВАШ-ЛОГИН.github.io/curiosity-day/`
   - В Redirect URLs добавьте тот же адрес и `http://localhost:5173/curiosity-day/`.
5. **Применить миграции.** После каждого этапа, где агент создал новые файлы в `supabase/migrations/`: откройте SQL Editor в Supabase, вставьте содержимое нового файла и нажмите Run. Файлы запускайте по порядку номеров, каждый один раз.

### 3. Вход через Google

1. Зайдите на console.cloud.google.com под своим Google-аккаунтом и создайте проект (например, «Curiosity Day»).
2. APIs & Services → **OAuth consent screen** (экран согласия):
   - тип пользователей — External;
   - название приложения — Curiosity Day, почта поддержки — ваша;
   - области доступа добавлять не нужно (достаточно email, profile, openid);
   - когда дойдёте до статуса публикации, переведите приложение **In production** (Publish app). Иначе войти смогут только добавленные тестовые пользователи, и друзья не смогут зарегистрироваться. Для этих базовых данных проверка Google не требуется.
3. APIs & Services → Credentials → Create credentials → **OAuth client ID**:
   - тип — Web application;
   - Authorized redirect URIs: `https://ИДЕНТИФИКАТОР-ПРОЕКТА.supabase.co/auth/v1/callback`. Точный адрес показан в Supabase: Authentication → Sign In / Providers → Google (поле Callback URL).
4. Скопируйте **Client ID** и **Client Secret**.
5. В Supabase: Authentication → Sign In / Providers → **Google** → включите, вставьте Client ID и Client Secret, сохраните.
6. Client Secret вставляется только в Supabase. В код, в репозиторий и в чат он не попадает.

#### Ссылки для Google Cloud

Чтобы перевести вход в режим «для всех», в Google Auth Platform → **Branding** нужны публичные ссылки. Страницы лежат в приложении и открываются без входа:

- Application home page → `https://sunny-bluesky.github.io/curiosity-day/about.html`
- Application privacy policy link → `https://sunny-bluesky.github.io/curiosity-day/privacy.html`
- Application terms of service link → `https://sunny-bluesky.github.io/curiosity-day/terms.html`

Исходные тексты страниц — в `design/legal/`, готовые страницы — `public/about.html`, `public/privacy.html`, `public/terms.html`. Если меняется почта для обращений или другие данные, их надо поправить в трёх HTML-файлах.

### 4. Claude Code

Разработку ведёт Claude Code. Он входит в вашу подписку Claude, лимиты общие с обычным чатом.

1. Скачайте или откройте Claude Code (в приложении Claude на компьютере или по инструкции в документации Anthropic) и войдите в свой аккаунт Claude. Названия пунктов зависят от версии.
2. Откройте в нём папку проекта `curiosity-day` (ту, куда клонирован репозиторий). В папке должны лежать `TZ.md`, `AGENTS.md`, `CLAUDE.md`, `README.md` и `design/`.
3. Первое сообщение: «Прочитай `TZ.md` и `AGENTS.md`. Сначала посмотри, что уже есть в папке: часть могла остаться от прошлого агента, предложи, что оставить, а что убрать. Затем выполни только этап 0 и остановись. Напиши, что мне проверить руками.»
4. Дальше этап за этапом: после каждого этапа проверяйте результат на телефоне и отвечайте, переходить ли дальше.
5. Claude Code спрашивает разрешение на команды. Читайте их так же внимательно, как в любом агенте: безопасны пути внутри проекта, `npm`, `git`, скачивание с официальных сайтов. Насторожитесь, если в команде есть `sudo`, `~/`, `/Users/`, «Документы», «Рабочий стол», `.ssh`, или `rm -rf` с путём вне проекта.
6. Если агент просит Node.js, установите Node.js LTS с nodejs.org обычным установщиком.
7. Если пуш в GitHub не проходит, попросите: «Настрой мне вход в GitHub для пуша, объясни простыми шагами».
8. Если агент просит значения ключей для локального запуска, он создаст файл `.env.local` с теми же `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Этот файл не попадает в репозиторий.
9. Если лимит подписки закончился, дождитесь сброса и продолжите с того же места: работа идёт этапами и сохраняется на GitHub после каждого.

## Как проверять на телефоне

**Установить на экран.**
- iPhone: откройте сайт в Safari → «Поделиться» → «На экран “Домой”».
- Android: откройте сайт в Chrome → меню (три точки) → «Установить приложение» или «Добавить на главный экран».

**Что смотреть после каждого этапа:** агент даст короткий список. Общее правило: открыть по ссылке, обновить страницу, закрыть и открыть заново, проверить на втором устройстве или втором аккаунте.

## Частые проблемы

- **Белая страница после выкладки.** Проверьте в Settings → Pages, что Source — GitHub Actions, и что в Actions последняя сборка зелёная. Подождите 1–2 минуты после сборки.
- **Страница открывается, но данные не грузятся.** Проверьте, что в секретах GitHub Actions указаны оба ключа без пробелов и что после добавления секретов сборка запускалась заново.
- **Вход через Google выдаёт ошибку redirect_uri_mismatch.** Адрес в Google Cloud (Authorized redirect URIs) должен совпадать с Callback URL из Supabase до символа.
- **Войти могу только я, друзья не могут.** Экран согласия Google в статусе Testing. Переведите приложение в In production.
- **После входа возвращает на другой адрес или на ошибку.** Проверьте Site URL и Redirect URLs в Supabase (шаг 2.4).
- **В установленном на iPhone приложении вход не сохраняется.** Известное ограничение iOS: установленное приложение хранит сессию отдельно от Safari. Сообщите агенту, он поправит способ входа.
- **Иконка не обновилась на телефоне.** Удалите установленное приложение с экрана и установите заново.
