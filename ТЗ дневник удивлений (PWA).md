# ТЗ: дневник удивлений (PWA)

Oct 26, 2026 · @Ксюша

## Цель и контекст

Маленькое мобильное приложение-дневник, в котором человек записывает удивившее и необычное, сделанное самим, и свои выводы. Нужно для автора и её друзей. Главная цель — работающая минимальная версия, выложенная в сеть за 1–2 дня. Идеальный результат не нужен, нужен рабочий.

**Зачем пользователю.** Когда жизнь идёт по рутине, дни слипаются в один. Записи становятся якорями, к которым можно вернуться. Человек сам создаёт значимые события: фиксирует удивительное и делает необычное. Календарь показывает, какие разные получаются дни, а лента позволяет перечитать свои впечатления.

**Задачи пользователя**

1. Пробовать новое.
2. Замечать интересное.
3. Видеть, чем прошедшие недели отличаются друг от друга.
4. Делать выводы.

**Язык интерфейса:** русский. **Разработка:** агентская, через Claude Code. Автор не сможет проверять и править код, поэтому решения выбираются максимально надёжные и простые.

## Границы MVP

P0 — то, что делается за первый день, это и есть MVP. P1 — то, что делается в следующие два дня. P2 — после запуска. P1 и P2 в MVP не входят, но структура данных и код не должны закрывать к ним путь.

**P0 — первый день, без этого приложение не работает**

- Вход через Google
- Три типа записей: «Удивило», «Сделано», «Вывод». Вывод можно привязать к нескольким записям и другим выводам
- Лента записей
- Календарь и статистика
- Автоматическое назначение маркера (формы и цвета) каждому дню
- PWA: установка на экран телефона

**P1 — следующие два дня после запуска P0**

- Фото к записи
- Ручная настройка формы и цвета маркера дня, назначение цвета по смыслу
- Вывод за неделю
- События аналитики
- Вход по email (ссылка или код), если будет почтовая служба
- Онбординг (экраны, тексты, возможность вернуться к подсказкам). Нужно доделать

**P2 — после запуска**

- Напоминания утром и вечером
- Аудио
- Теги
- Офлайн-режим и push-уведомления

## Платформа и технический стек

Приложение — PWA: мобильный сайт, который можно установить на экран телефона. Макеты есть только для мобильной версии. Десктопную вёрстку агент делает сам, без отдельного дизайна: приложение должно нормально открываться, например, колонкой фиксированной ширины по центру.

**Название:** Curiosity Day. Короткое имя под иконкой: Curiosity. Репозиторий: `curiosity-day`, адрес сайта: `https://<логин>.github.io/curiosity-day/`.

| Что | Выбор |
| --- | --- |
| Фреймворк | React + Vite + TypeScript |
| Стили | Tailwind CSS |
| Роутинг | React Router в режиме HashRouter (адреса вида `/#/stats`) |
| База и вход | Supabase, клиент supabase-js |
| PWA | vite-plugin-pwa: манифест, иконки, установка на экран |
| Календарь и статистика | пишутся вручную, без тяжёлых библиотек |

**Правила для агента**

- Новые библиотеки добавлять только по согласованию с автором. Исключение: lucide-react для обычных иконок интерфейса (плюс, троеточие, галочка, стрелка назад, профиль и т.п.). SF Symbols использовать нельзя, лицензия Apple разрешает их только в приложениях для платформ Apple. Значок «Aa» делается текстом. Иконки типов записей и маркеры дней — SVG автора.
- После каждого этапа запускать сборку, проверку типов и линтер и исправлять ошибки до результата без предупреждений.
- Приложение живёт в подпапке `/<имя-репозитория>/`, поэтому базовый путь в настройках сборки должен быть задан явно.
- HashRouter нужен, потому что у GitHub Pages нет серверных редиректов и обновление страницы на вложенном адресе иначе даёт 404.
- В PWA на MVP только манифест и установка. Service worker, офлайн-режим и push не делаются.
- Состояния загрузки, ошибки и отсутствия сети агент делает сам, простыми стандартными решениями. Макетов для них нет.

## Деплой и ключи Supabase

Хостинг — GitHub Pages, база данных — Supabase. Деплой автоматический через GitHub Actions: при каждом обновлении главной ветки приложение собирается и публикуется.

- **Публичный ключ (anon key)** и адрес проекта Supabase хранятся в настройках репозитория и подставляются при сборке. В коде сайта они видны, это нормально.
- **Секретный ключ (service\_role) нельзя использовать в приложении и класть в репозиторий ни при каких условиях.**
- Защита данных держится на правилах доступа в базе (RLS). RLS включается на каждой таблице в SQL-миграциях, и каждый пользователь видит и меняет только свои строки.
- В репозитории лежит файл `.env.example` с названиями переменных без значений.
- Пошаговая инструкция для автора (создать репозиторий, проект Supabase, добавить переменные, включить Pages) пишется в README.

## Экраны и сценарии по wireframes

Wireframes серые, но приложение цветное. Цвет принципиально важен на экране статистики.

### Главный экран

- Сверху полоса дней: семь дней в ряд, текущий день выделен, под полосой подписаны месяцы.
- У дней с записями в полосе показан маркер дня, выбранный день выделен цветом своего маркера. Дата в редакторе тоже отмечена маркером дня.
- Справа вверху иконка профиля. Она ведёт на экран статистики.
- В центре лента записей: все записи подряд, от последней к первой, по дате впечатления. Нажатие на день в полосе прокручивает ленту к записям этого дня. Выбранный день в полосе определяет, на какую дату создаётся новая запись. Будущие дни недоступны. В пустом состоянии в центре мягкое размытое пятно.
- Внизу заголовок «Что интересного сегодня?» и три кнопки: «Удивило», «Сделано», «Вывод». Подписи нейтральные по роду, пол пользователя не спрашивается.

### Лента и выбор записей для вывода

- Карточка записи: заголовок или первые строки текста, значок типа записи в конце текста. Миниатюра фото слева появляется вместе с фото (P1). Вывод показан карточкой с крупным значком вывода слева.
- При прокрутке вверх пространство для просмотра раздвигается: верхняя часть экрана сжимается, заголовок и кнопки уходят. При прокрутке вниз обычный вид возвращается.
- Вывод можно написать по нескольким записям. Свайп карточки вправо добавляет её к выводу, слева от карточки появляется значок вывода. Выбрать можно любое число записей любого типа, в том числе другие выводы.
- После выбора нажатие на кнопку «Вывод» внизу или на значок вывода у карточки открывает редактор вывода: выбранные записи показаны свёрнутыми карточками, ниже поле для текста.
- Кнопка «Вывод» без выбранных записей создаёт вывод без привязки.
- Вывод можно создать и из редактора записи по стрелке. Тогда он привязан к этой одной записи.
- Связи задаются только при создании вывода. Добавлять и удалять записи в уже созданном выводе в MVP нельзя.
- В ленте не показывается, что у записи есть вывод. Связь записи с выводом внутри карточки будет решена отдельно.
- Сжатие верхней части экрана при прокрутке желательно, но не критично: если не получится, остаётся обычная верхняя часть.

### Редактор записи

- Открывается по нажатию на любую из трёх кнопок сразу с поднятой клавиатурой.
- Дата впечатления проставляется автоматически из дня, выбранного на главной (например, «1 октября 2026»). Её можно поменять в самом редакторе при создании и при редактировании, через системный выбор даты. Будущие даты выбрать нельзя.
- Сначала пишется заголовок. После первого нажатия Enter курсор переходит в обычный текст. Дальше Enter делает перенос строки.
- Плейсхолдеры: для «Удивило» — «Запиши, что удивило», для «Сделано» — «Запиши, что удивительного сделано». Редактор «Сделано» такой же, как «Удивило»: отличаются только значок типа записи вверху по центру и плейсхолдер.
- Кнопка «…» открывает настройки записи. В MVP там удаление записи и информация о записи: дата впечатления и дата, когда запись написана.
- Сохранённую запись можно менять: текст и дату. При удалении записи выводы, привязанные к ней, остаются и просто теряют эту привязку.
- Панель над клавиатурой: «+» (добавить фото и ссылки), «Aa» (изменить ввод текста), стрелка (написать вывод), галочка (сохранить).
- Nice to have: по нажатию на иконку типа записи появляется подсказка, что писать и зачем.

### Режим вывода

- Открывается по нажатию на стрелку в панели редактора.
- Исходная запись сворачивается в карточку: заголовок и первые три строки текста. Внутри карточки можно прокручивать текст.
- Ниже новое поле с плейсхолдером «Запиши мысль, появившуюся на основе нового опыта».

### Запись с фото (P1)

- Первое фото показывается в ленте.
- В редакторе фото сжато сверху. При прокрутке верхняя навигация остаётся на месте, а фото и заголовок уезжают.

### Статистика

- Стрелка назад и заголовок вида «24 удивительных дня!».
- Три счётчика по типам записей с теми же подписями, что и кнопки на главном экране: «Удивило», «Сделано», «Вывод». В wireframe статистики ещё старые подписи, брать нужно новые.
- Переключатель периода: «Неделя», «Месяц», «Год».
- Календарь месяца, где дни с записями отмечены цветными маркерами разной формы.
- Название экрана: «Моя статистика». Блок «Мои данные» (имя, удаление аккаунта) есть на макете, но в MVP не делается.

## Вход, пользователи, приватность

- **Основной вход — через Google** (Supabase Auth, провайдер Google). Автор один раз создаёт OAuth-ключ в Google Cloud, инструкция идёт в README.
- **Вход по email** (ссылка или код из письма) в MVP не делается. Встроенная почта Supabase отправляет письма только участникам команды проекта и не более 2 в час, поэтому для друзей нужна внешняя почтовая служба (custom SMTP). Это P1.
- **Социальных функций нет.** Шаринг записей — в будущих релизах.
- Каждый пользователь видит и меняет только свои данные (RLS на всех таблицах).
- Имя пользователя берётся из Google-аккаунта. Отдельной анкеты профиля нет.
- Регистрация открыта для всех, у кого есть ссылка.
- Подписи кнопок нейтральные, поэтому пол в профиле не хранится и анкета пола не нужна.
- Проверить руками: вход через Google внутри установленного PWA на iPhone. На iOS установленное приложение хранит сессию отдельно от Safari.

## Модель данных (Supabase, Postgres)

Схема создаётся SQL-миграциями в папке `supabase/migrations/`. Автор применяет их вручную в редакторе SQL в Supabase (инструкция в README), консольные инструменты не нужны. На всех таблицах включён RLS: пользователь читает и меняет только строки со своим `user_id`.

**profiles**

- `id` (uuid, ключ, ссылка на пользователя auth), `display_name` (имя из Google-аккаунта), `created_at`.
- Строка создаётся автоматически триггером при первой регистрации.

**entries** — все три типа записей

- `id`, `user_id`, `type`: `noticed` («Удивило»), `did` («Сделано»), `conclusion` («Вывод»).
- `title` (может быть пустым), `body`.
- `entry_date` (date) — день впечатления, `created_at` и `updated_at` (timestamptz) — когда запись написана и изменена.
- Дата берётся с устройства пользователя как локальная дата, пересчёта часовых поясов нет. Будущие даты запрещены в интерфейсе.
- Индекс по `(user_id, entry_date desc, created_at desc)`. Лента сортируется так же: сначала по `entry_date`, затем по `created_at`.

**entry\_links** — связь вывода с записями (многие ко многим)

- `conclusion_id`, `source_id` (обе ссылки на `entries`), `user_id`. Ключ — пара `(conclusion_id, source_id)`.
- Источником может быть запись любого типа, в том числе другой вывод.
- При удалении записи-источника удаляется только связь, вывод остаётся. При удалении вывода удаляются его связи.
- Политика RLS проверяет, что обе записи принадлежат пользователю.
- Связи создаются только при создании вывода. Изменение связей в MVP не делается.

**day\_markers**

- `user_id`, `day` (date), `shape`, `color`. Ключ — пара `(user_id, day)`.
- Строка создаётся при первой записи на этот день (вставка с игнорированием, если уже есть) и никогда не удаляется вместе с записями.
- `shape` — имя формы из набора SVG, `color` — имя цвета из палитры day-\*.

**Подсчёты для статистики** делаются на клиенте по записям выбранного периода: дни с записями, число записей по типам. Для MVP все записи загружаются целиком, пагинация не нужна.

**Позже (P1)**

- `entry_photos` и бакет Storage для фото.
- `events` для аналитики.
- Тип `week_conclusion` в `entries`.

## Маркеры дней и статистика

- У каждого дня один маркер: форма и цвет. Маркер привязан к дате впечатления, а не к моменту написания записи.
- Маркер назначается автоматически при появлении первой записи на этот день, в каком бы порядке ни заполнялись дни.
- Маркер хранится в базе. Если удалить все записи за день, маркер исчезает из календаря, но сохраняется. При новой записи на этот день возвращаются прежние форма и цвет.
- В календаре маркеры показаны только у дней, где есть записи.
- Ручная настройка формы и цвета — P1.

В MVP (P0) цвет и форма только отличают дни друг от друга. Автоматический выбор случайный, с проверкой, чтобы соседние дни не получали одинаковое сочетание формы и цвета. Назначение цвета по смыслу делается в P1. Набор форм (SVG) и палитра приходят от автора, см. раздел «Что требуется от автора».

Формы и цвета автор передаст позже. До этого агент использует временные простые SVG-формы. Цвета маркеров берутся из палитры day-\* (см. «Дизайн и ассеты»). Формы и палитра лежат в одном месте (отдельная папка с SVG и один файл настроек), чтобы замена сводилась к подмене файлов без правки логики.

## Открытые вопросы

## Критерии готовности и план задач

**Общие правила.** Работа идёт этапами. После каждого этапа агент запускает сборку, проверку типов и линтер, коммитит и выкладывает на GitHub Pages. Приложение должно быть рабочим после любого этапа. Автор проверяет результат на телефоне по ссылке и чек-листу этапа. Лимиты подписки автора общие с чатом, поэтому агент не делает лишних действий, а если лимит кончился, работа продолжается после сброса с последнего завершённого шага.

**Этап 0. Каркас и деплой**

- Репозиторий, Vite + React + TypeScript, Tailwind, HashRouter, PWA-манифест, иконки, шрифт Inter.
- GitHub Actions: сборка и публикация на Pages при каждом обновлении главной ветки.
- Готово, когда: страница открывается по ссылке на телефоне, её можно установить на экран, иконка и название верные.

**Этап 1. Supabase и вход**

- Миграции: `profiles` с триггером, RLS. Вход через Google, выход, защита экранов от неавторизованных.
- Готово, когда: вход работает в браузере телефона и в установленном PWA, сессия сохраняется после перезапуска, у двух разных аккаунтов данные не пересекаются.

**Этап 2. Записи и лента**

- Главный экран, редактор для «Удивило» и «Сделано» (заголовок, затем текст, дата, сохранение), редактирование и удаление, информация о записи в «…», лента от последней к первой.
- Готово, когда: запись создаётся, меняется, удаляется и видна в ленте после перезагрузки. Будущую дату выбрать нельзя. Запись за прошлый день попадает в свой день.

**Этап 3. Полоса дней, маркеры, статистика**

- Полоса дней на главной с маркерами, нажатие на день прокручивает ленту. Автоматические маркеры (случайно, без повторов у соседних дней). Экран «Моя статистика»: заголовок с числом дней, счётчики по типам, переключатель «Неделя / Месяц / Год», календарь.
- Готово, когда: у дней с записями есть маркер, он сохраняется при удалении записей и возвращается при новой записи, счётчики совпадают с реальным числом записей.

**Этап 4. Вывод**

- Кнопка «Вывод» без выбора и со стрелкой из редактора. Выбор нескольких карточек свайпом вправо, редактор вывода со свёрнутыми карточками, сохранение связей. Удаление источника не удаляет вывод.
- Готово, когда: вывод создаётся по нескольким записям и по другим выводам, вертикальная прокрутка ленты не ломается, свайп не срабатывает случайно.

**Этап 5. Доводка**

- Состояния загрузки, ошибок и отсутствия сети, сжатие верхней части ленты при прокрутке (если получится), проверка на iPhone и Android, вычитка текстов.
- Готово, когда: все чек-листы этапов пройдены на двух устройствах, README описывает запуск и настройку с нуля.

**После MVP (P1, следующие два дня):** фото, аналитика, онбординг, вывод за неделю, ручная настройка маркеров, вход по email.
