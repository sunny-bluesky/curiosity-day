# AGENTS.md — правила для агента

Проект: **Curiosity Day** — мобильное PWA-приложение, дневник впечатлений. Полное описание продукта, экранов, данных и этапов — в `TZ.md`. Макеты, SVG-формы маркеров, иконки и иконка PWA — в папке `design/`.

## Кто автор и как с ним общаться

- Автор — продуктовый дизайнер, код не читает и не правит. Всё должно работать без ручных правок кода.
- Отвечай автору по-русски, простыми словами, без жаргона. Коротко: что сделано, что проверить руками на телефоне.
- Тексты интерфейса — русские. Имена в коде, комментарии и коммиты — английские.

## Как работать

1. Работай **строго по этапам** из `TZ.md` (раздел «Критерии готовности и план задач»). Делай один этап за раз.
2. После этапа: запусти сборку, проверку типов и линтер, исправь все ошибки и предупреждения, сделай коммит, запушь в главную ветку (деплой на GitHub Pages запускается автоматически).
3. Затем остановись и напиши автору короткий чек-лист «что проверить на телефоне». К следующему этапу переходи только после слов автора.
4. Приложение должно оставаться рабочим после каждого этапа. Не оставляй сломанное состояние между этапами.
5. В MVP делай только P0. Не добавляй P1 и P2 (фото, аналитика, онбординг, вывод за неделю, ручная настройка маркеров, вход по email, напоминания, аудио, теги, блок «Мои данные»), но не закрывай к ним путь в структуре данных и кода.
6. Если чего-то нет в `TZ.md` или на макетах (состояния загрузки, ошибки, пустые состояния), выбери простое стандартное решение в стилистике приложения и коротко сообщи об этом. Не останавливайся из-за мелочей. Остановись и спроси автора, только если решение необратимо или меняет ТЗ.

## Стек (зафиксирован)

React + Vite + TypeScript, Tailwind CSS, React Router в режиме **HashRouter**, supabase-js, vite-plugin-pwa. Календарь и статистику пиши сам, без тяжёлых библиотек.

- **Новые библиотеки добавлять нельзя без согласования с автором.** Для свайпа карточек используй собственные pointer/touch-обработчики.
- **Исключение, согласованное с автором: `lucide-react`** для обычных иконок интерфейса (плюс, троеточие, галочка, стрелка назад, профиль, календарь и т.п.). SF Symbols использовать нельзя: их лицензия запрещает применение вне платформ Apple. Значок «Aa» делай обычным текстом. Иконки трёх типов записей и маркеры дней — только SVG автора из `design/`.
- Vite `base` = `/curiosity-day/`. Приложение живёт в подпапке, учитывай это во всех путях (иконки, манифест, ассеты).
- PWA в MVP: только манифест и установка на экран. Без service worker, офлайн-режима и push.
- Название: **Curiosity Day**, короткое имя под иконкой: **Curiosity**.

## Безопасность и ключи

- В приложении используется только публичный ключ Supabase (anon key). Переменные: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Локально — в `.env.local` (не коммитить), для сборки — секреты репозитория GitHub Actions. В репозитории лежит `.env.example` без значений.
- **Секретный ключ (service_role), Client Secret Google и любые пароли никогда не попадают в код, репозиторий, логи и ответы.**
- RLS включён на всех таблицах. Каждый пользователь читает и меняет только свои строки. После каждой миграции проверяй, что политики есть на всех таблицах.
- Миграции — SQL-файлы в `supabase/migrations/` с порядковыми номерами. Применённые файлы не менять, изменения — новыми файлами. Автор запускает их вручную в редакторе SQL Supabase, поэтому каждый файл должен быть самодостаточным и безопасным для однократного запуска.

## Дизайн

- Шрифт: **Inter**.
- Цвета — таблица в разделе «Дизайн и ассеты» `TZ.md`. Держи все цвета в одном файле (например, `src/theme/colors.ts`) и подключай через Tailwind. Фон белый, текст `#4C4C4C`, акцент `#0088FF`.
- Формы маркеров — SVG из `design/markers/`, иконки типов записей — из `design/icons/`. Если файлов нет, используй временные простые формы в одном месте, чтобы замена свелась к подмене файлов.
- **Приоритет источников.** Поведение и логика — `TZ.md` (главный источник). Внешний вид — цветные макеты из `design/mockups/` и таблица цветов. Серые wireframes (файлы с префиксом `wireframe-`) нужны ради заметок о поведении на них (Enter, свайп, прокрутка); цвета и старые подписи кнопок («Заметила», «Сделала») на них устарели. При расхождении побеждает `TZ.md`.
- Макеты мобильные. На широком экране показывай колонку фиксированной ширины (до 480 px) по центру.
- Типы записей: `noticed` — «Удивило» (peach), `did` — «Сделано» (mellon), `conclusion` — «Вывод» (apple).

## Поведение, на которое стоит обратить внимание

- **Даты.** `entry_date` — локальная дата устройства, без пересчёта часовых поясов. Будущие даты недоступны везде (полоса дней, выбор даты). Лента: от последней записи к первой, сортировка по `entry_date`, затем по `created_at`.
- **Маркеры дней.** Один на день, назначаются случайно при первой записи на этот день (соседние дни не получают одинаковое сочетание формы и цвета). Строка маркера не удаляется вместе с записями.
- **Редактор.** Первая строка — заголовок, после первого Enter — основной текст. Запись можно менять после сохранения (текст и дату).
- **Свайп карточек (этап 4).** Срабатывает только при явном горизонтальном сдвиге вправо. Вертикальная прокрутка и системный жест «назад» на iPhone не должны ломаться (`touch-action: pan-y`, порог срабатывания).
- **Удаление записи.** Привязанные к ней выводы остаются и теряют только связь.
- **Вход.** Только Google через Supabase Auth. Проверь вход внутри установленного PWA на iPhone.

## Состояние проекта и лимиты

- В начале работы посмотри, что уже есть в папке проекта. Часть могла остаться от прошлого агента (папки `.tools` и `.scaffold`, заготовка Vite). Предложи автору, что оставить, а что убрать. Удалять можно только после согласия автора. Папки `.tools`, `.scaffold`, `node_modules`, `dist` и файл `.env.local` должны быть в `.gitignore`.
- Проверь, установлен ли Node.js (`node -v`). Если нет, скажи автору, что нужно установить Node.js LTS с nodejs.org обычным установщиком. Не скачивай и не распаковывай Node в папку проекта.
- Для пуша в GitHub может понадобиться вход в аккаунт на компьютере автора. Если пуш не проходит, объясни автору простыми шагами, как настроить вход, и не обходи защиту.
- Лимиты подписки автора ограничены. Не читай лишние файлы, не запускай лишние сборки и не переписывай то, что уже работает. Если лимит кончился, остановись на завершённом шаге и скажи автору, что именно сделано и с чего продолжать.

## Определение «готово»

- Сборка, проверка типов и линтер проходят без ошибок и предупреждений.
- Свежая версия выложена на GitHub Pages и открывается по ссылке.
- Пройден чек-лист этапа из `TZ.md`, автор получил список для проверки руками.
